# アプリ量産用アーキテクチャ（無料前提）

## 概要

複数の異なるアプリを独立してデプロイしつつ、コストを抑えるための構成。

- 各アプリは完全に独立
- サーバーは持たず、サーバーレス中心
- 認証は外部サービスに委譲

---

## 構成

[ Frontend ]
Cloudflare Pages

[ Backend (API) ]
Pages Functions

---

## 役割分担

### 1. Cloudflare Pages
- フロントエンドのホスティング
- 静的ファイル配信
- 各アプリごとに独立デプロイ

---

### 2. Pages Functions
- 軽量なバックエンド処理
- APIエンドポイントの提供
- 認証チェック（JWT検証）
- 外部API連携

※ 必要な場合のみ使用

---

### 3. Google認証
- 認証（Auth）

### 4. cloud flare D1
- データベース

### 5. cloud flare R2
- ストレージ、写真、ファイル

---

## Pages Functions の役割

### やること
- サーバー側ロジック
- 外部API呼び出し
- セキュア処理

### やらないこと
- 認証処理そのもの

---

## Functions が必要なケース

- 外部API連携
- サーバー側でのみ実行すべき処理
- 複雑なビジネスロジック
- 秘密情報を扱う処理

---

## Functions が不要なケース

- 単純CRUD
- ユーザー自身のデータ取得
- フォーム送信
- 一般的なUI操作

---

## この構成のメリット

- サーバー不要（低コスト）
- アプリをいくらでも増やせる
- デプロイがシンプル
- 認証を自前実装しなくて良い
- スケーラブル

---

## この構成の制約

- 重い処理には不向き
- 長時間処理不可
- 複雑なバックエンドには限界あり

---

## 結論

認証 → Google認証
DB → Cloudflare D1
フロント → Cloudflare Pages
API → 必要な分だけ Pages Functions
